# Design

Visual mockups for the game's UI, exported from [Claude
Design](https://claude.ai/design). **Reference material, not source.** Nothing
here is compiled, imported or served — `frontend/` is built by hand from it.

## Files

| File | What it is |
|------|-----------|
| `Cycling Manager UI.dc.html` | The mockup: three screens in one file |
| `support.js` | The Claude Design runtime the export needs to render |
| `.thumbnail` | Preview image generated by the exporter |

## Viewing it

Open the `.html` file in a browser. It is self-contained apart from Google
Fonts.

## What it contains

Three screens, switched by the sidebar:

- **Dashboard** — built, see `frontend/src/screens/Dashboard.tsx`
- **Roster** — built, see `frontend/src/screens/Roster.tsx`
- **Race day** — *not built*. `race_player/` already visualizes races; whether
  that becomes this screen or stays separate is an open question.

Any other sidebar item falls through to the Dashboard in the mockup. The real
app routes those to a placeholder instead, so a click's outcome is visible.

## How to read it

It is authored in Claude Design's own template DSL, not plain HTML:

- `{{ expr }}` — a binding, resolved by the `<script type="text/x-dc">` block
  at the bottom of the file
- `<sc-for list="{{ xs }}" as="x">` — a loop
- `<sc-if value="{{ cond }}">` — a conditional
- `style-hover="…"` — a hover state (React has no inline equivalent; these
  became classes in `frontend/src/index.css`)

The script block at the end holds all the sample data — squad, results, league
table, course profile. That data was transcribed into
`frontend/src/placeholderData.ts`, and the colours into
`frontend/src/theme.ts`.

## When it changes

On a re-export, reconcile in this order: `theme.ts` (colours, fonts), then
`placeholderData.ts` (copy and numbers), then the screens. Do not try to make
the export runnable — translating it is the workflow.
